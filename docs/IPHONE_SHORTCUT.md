# iPhone 快捷指令 → 飞书每日工作日记 → 工作台

这条链路不把飞书凭证放进 iPhone。快捷指令只携带一个专用的 `CAPTURE_TOKEN`，请求工作台的采集接口；工作台在已登录的本机 `lark-cli` 下完成以下原子流程：

```text
iPhone 听写/输入
  → POST /api/capture
  → 工作台调用 lark-cli 写入飞书“收件箱”章节
  → 工作台读回飞书新增 block
  → 读回成功后才提交本地收件箱缓存
```

因此，快捷指令成功返回时，事项已经同时进入飞书文档和工作台收件箱，不需要再调用第二个同步接口。飞书里手动新增的 `[INBOX]` 条目，仍可在工作台点击“同步飞书收件箱”读回。

## 1. 先让 iPhone 能访问工作台

手机和运行工作台的 Mac 必须在同一个局域网。先在 Mac 上查当前 Wi‑Fi IPv4 地址，再把下面的 `<Mac局域网IP>` 替换成实际地址，在 iPhone Safari 打开：

```text
http://<Mac局域网IP>:4173
```

如果 Safari 打不开，先检查：

- Mac 工作台已用 `HOST=0.0.0.0` 启动，而不是只监听 `127.0.0.1`；
- iPhone 与 Mac 连接同一个 Wi-Fi，且没有启用“隔离客户端”的访客网络；
- Mac 防火墙允许 Node 接收入站连接；
- 当前这台 Mac 的实测地址曾是 `192.168.31.100`；如果地址发生变化，以 Mac 当前 Wi-Fi IPv4 地址替换。

局域网 HTTP 只适合可信家庭/办公网络。离开局域网时不要把这个端口直接暴露到公网；需要外网访问时，改用 Tailscale 或 HTTPS 反向代理，并同步更新 `TRUSTED_ORIGINS`。

## 2. 新建快捷指令

在 iPhone“快捷指令”中新建一个快捷指令，按以下顺序添加动作：

1. 添加“听写文本”（也可以改成“询问输入”）。
2. 添加“获取 URL 内容”。
3. URL 填：

   ```text
   http://<Mac局域网IP>:4173/api/capture
   ```

4. 展开“获取 URL 内容”的高级选项：
   - 方法：`POST`
   - 请求体：`JSON`
   - JSON 字段 `text`：选择上一步的“听写文本”变量
   - JSON 字段 `source`：填写 `iphone-shortcut`
   - 请求头 `Authorization`：填写 `Bearer ` 加上本机 `.env` 中的 `CAPTURE_TOKEN`
   - 请求头 `Content-Type`：`application/json`（如果界面已自动生成，可不重复添加）
5. 最后添加“显示通知”，例如“已写入飞书并进入工作台收件箱”。测试时建议先保留“显示结果”，确认返回 JSON 后再改成通知。

不要把飞书 access token、app secret、cookie 或 `lark-cli` 登录文件放进快捷指令。快捷指令会进入 iCloud/设备备份，只有采集 token 可以出现在这里；如需分享快捷指令，先删除或重新轮换该 token。

## 3. 绑定语音入口

可以把快捷指令绑定到“轻点背面”双击、Siri，或主屏幕快捷方式：

`设置 → 辅助功能 → 触控 → 轻点背面 → 双击 → 选择这个快捷指令`

## 4. 成功与失败怎么判断

- 成功：快捷指令收到 HTTP `201`，返回的 `item.source` 为 `feishu_doc`；这表示飞书写入、飞书读回和本地缓存提交均已完成。
- 飞书失败：接口返回 `502` 或其他错误，工作台不会伪装成已同步；先检查 Mac 的 `lark-cli` 登录状态和文档编辑权限。
- 未授权：返回 `401`，通常是 token 复制错误、前缀缺少 `Bearer `，或 `.env` 变更后服务尚未重启。
- 同步过频：返回 `429`，按响应中的 `Retry-After` 秒数等待，不要在快捷指令里循环重试。

## 5. 工作台中的后续动作

事项只会进入“收件箱”，不会自动分类、不会自动变成待办、不会补截止日期，也不会自动加入“今日工作台”。在工作台收件箱中由你明确选择“项目 / 待办 / 备忘 / 删除”；只有你明确加入的待办才会进入今日计划。
