# 产品规则（v1.2.0）

> 收件箱可绑定飞书每日工作日记。飞书文档中的一级“收件箱”章节是外部来源；只有 `[INBOX]` 前缀条目才进入工作台，其他日记正文不自动转任务。

## 产品定位

这是一个以业务板块和项目为上下文边界的个人 AI 项目管理工作台。目标不是增加任务管理动作，而是让用户在频繁被打断后，可以快速恢复工作现场。

## 最高数据规则

**本地文件夹是真实工作产物源；Git 是版本证据源；飞书项目云文档是项目分析、阶段总结、复盘与长期叙事记忆的唯一真源；Workbench 只保存运行所需的最小结构化状态、引用和同步游标。**

这意味着：

- 项目分析正文、卡点说明、恢复摘要、阶段总结、复盘正文不得复制进 `state.json`、`PROJECT.md` 或本地 activity 日志。
- Workbench 可以保存机器需要的 `percent / status / hasBlocker / lastActivity / syncedAt / confidence`，以及飞书 revision/block 指针。
- `PROJECT.md` 只是项目身份证和入口索引，不是项目分析报告。
- 工作日志是审计日志，不等同于人的项目总结或项目记忆。
- 如果项目没有绑定飞书项目文档，系统仍可计算机器进度，但分析正文不持久化，并进入“待确认”。

## AI-native 双面板

- 左侧固定为人的工作面板，右侧固定为 AI 控制平面；不是两个并列的管理面板。
- 右侧 AI 通过 `ai_console` 结构化工作流提出一个白名单 MCP 工具调用或澄清问题；模型不能直接执行、访问任意 URL、shell、文件路径或凭证。
- 本地 MCP 注册表负责工具 schema 校验、确认门、领域规则和执行后状态读回；左侧和右侧共享同一个持久化状态源。
- 模型未配置、不可达、输出不合约或工具参数不合法时，显式显示本地安全回退，不把回退伪装成模型判断。
- 每次工具调用都要在右侧显示工具名、参数、影响范围和执行/读回结果；写入动作必须由用户确认。
- 左侧导航也属于可被 AI 操作的工作台表面：AI 通过 `panel_navigate` 切换面板或打开设置/新建项目弹层；左侧负责呈现，右侧负责意图、工具预览和执行反馈。
- 项目叙事增加两个白名单工具：`project_records_read` 只从绑定飞书项目文档读取；`project_summary_append` 只向绑定文档追加阶段总结，且写入必须确认。

## 最高规则

**AI 可以分析、提醒、解释和执行明确指令，但不能替用户安排。**

以下动作必须由用户明确触发：
- 把任务加入今日工作台
- 改变待办截止日期
- 改变项目计划结束日期
- 把独立待办升级成项目
- 将收件箱内容移动到任何项目/待办
- 把待归类项目归入业务板块
- 向飞书项目文档追加人工阶段总结

## 信息结构

1. 收件箱：所有新增事项第一站。
2. 今日工作台：用户当天明确决定要做的待办。
3. 业务板块：一级导航和一级本地文件目录。
4. 项目：独立上下文容器。
5. 待确认：AI 无法可靠判断、需要用户拍板。
6. 待归类：业务归属不明确的项目。
7. 逾期：只放超过计划结束时间、尚未结束的项目。
8. 工作日志：机器审计日志，只记录关键动作，不保存项目分析正文。
9. 飞书项目文档：项目分析、阶段总结、复盘和长期叙事记忆的唯一真源。

## 项目规则

- 创建输入：自然语言项目描述 + 计划结束日期。
- 开始日期：默认创建当天。
- 计划结束日期：必须由用户明确，AI 不猜。
- 名称/介绍：AI 自动生成；无 AI 时本地规则生成。
- 业务归属：AI 置信度足够时可创建到对应板块；不确定则待归类。
- 中间里程碑：不要求用户维护，由 AI 从项目内容识别。
- 不存在“暂停状态”。
- 第一次真实文件创建/修改/保存或 Git 提交，在下一次同步时被识别为“进行中”。
- 项目首页固定关注：介绍、机器进度、计划结束时间、是否存在卡点、资料路径、飞书项目文档入口。
- 具体分析、卡点正文和上下文恢复摘要从飞书项目文档按需读取，不在项目首页本地复制。
- 不在项目首页自动生成“下一步动作”。

## 项目资料与记录边界

### 本地项目文件夹

真实工作产物来源：本地电脑项目文件夹。

默认目录：

```text
业务板块/
└── 项目/
    ├── PROJECT.md
    ├── 01_原始资料/
    ├── 02_工作过程/
    ├── 03_最终交付/
    └── 99_归档/
```

`PROJECT.md` 只保留：
- Project ID
- 项目名称/介绍
- 所属业务
- 开始日期/计划结束日期
- Git 仓库
- 飞书项目文档 URL
- “分析与总结真源：飞书云文档”声明

`PROJECT.md` 不保存：
- 进度说明正文
- 卡点正文
- 恢复摘要
- 阶段总结
- 复盘正文

### Workbench 本地状态

只保存机器运行字段：
- 本地路径
- Git 仓库
- 飞书项目文档 URL
- `percent`
- `status`
- `hasBlocker`
- `lastActivity`
- `syncedAt`
- `confidence`
- 最近一次飞书记录的 revision / block / recordedAt 指针

### 飞书项目文档

每个项目最多绑定一个 `project.feishu`，它代表该项目唯一的飞书项目文档。

工作台只操作一个固定一级章节：

```text
# 项目分析与总结
```

工作台生成的记录只使用固定前缀：

```text
[WORKBENCH_ANALYSIS] ...
[WORKBENCH_SUMMARY] ...
```

其他飞书正文不会被当作机器状态，也不会自动写回本地。

- `WORKBENCH_ANALYSIS`：主动项目同步生成的分析报告。
- `WORKBENCH_SUMMARY`：用户确认后追加的阶段总结/复盘记录。
- 读取项目记录时直接读取飞书，不把正文缓存到 `state.json`。
- 写入采用“飞书写入 → 飞书读回确认 → 本地只更新机器指针”的 remote-first 顺序。
- 飞书写入或读回失败时，不把分析正文伪装成本地已保存。

## 项目进度

- 不持续后台监控。
- 用户点击“同步所有项目进度”或单项目同步后才分析。
- 分析证据：目录文件、修改时间、文本片段、Git commit、Git remote。
- 默认 AI Provider Profile：`openai_luna`，模型 `gpt-5.6-luna`，固定使用极高推理档位 `xhigh`；部署管理员可以显式选择已注册且已批准的第三方兼容 Profile。
- 分析顺序固定为：先核对证据，再标注冲突与信息缺口，最后给出结构化结论。
- 模型只返回简短可审计依据；分析信封仅用于本次本机校验，不保存依据草稿或模型隐藏思维过程。
- 临时分析可以包含状态说明、百分比、卡点和恢复摘要；其中人类可读叙事只写入飞书项目文档。
- 飞书读回确认后，本地只提交机器进度和记录指针。
- 没有绑定飞书项目文档：允许更新机器进度，但分析正文不落地，并新增待确认提示。
- 信息不足：进入待确认，不反复弹窗。
- 项目目录不存在/不可访问：保留最后已知机器进度，降低置信度，不重建目录，并进入待确认。
- AI Provider 未配置、未启用、能力不匹配、超时、拒绝、不可达或结果校验失败：回退本地规则；不能让失败改变收件箱、截止日期或今日任务，也不能静默把数据转发给另一家云 Provider。
- `xhigh` 允许更充分地核对复杂证据，但会增加响应延迟和调用成本；模型档位本身不等于判断一定正确。

## 待办

- 项目待办和独立待办都允许。
- 新待办必须从收件箱经过用户指令产生。
- 必须有截止日期，只需要精确到日期。
- 用户没说截止日期，AI 必须追问。
- 截止日期到了也不会自动进入今日工作台。
- 自然语言项目名匹配到多个项目时，不按列表顺序猜测；收件箱保持原状并进入待确认，由用户明确选择项目后才创建项目待办或记录。

## 今日工作台与早晨对焦

AI 默认分析：
- 最近 3 天真实工作
- 最近 3 天新出现的待办
- 临近截止的项目和待办

已经逾期的项目放在逾期目录，不混入普通项目候选。

AI 通过简短对话提出值得讨论的事项，用户最终决定哪些待办加入今日；数量不设固定上限。

早晨对话也使用同一套“证据 → 冲突与缺口 → 最终结论”工作流；无论 AI 成功还是本地回退，都只给出讨论候选，不直接写入今日计划。

今日选择按服务所在机器的自然日记录：只有用户在当天明确加入的待办才对外显示为今日任务。日期变化后，昨日选择不会自动沿用；用户当天第一次加入或移出待办时，系统先建立当天的空计划，再执行本次明确操作。

## AI Provider 与数据边界

- 默认 `openai_luna` 保持既有 OpenAI Responses API 行为；程序同时提供受限的 Responses-compatible 与 Chat-Completions-compatible Adapter，但第三方 Profile 默认未启用，必须由部署管理员明确配置并批准。
- 业务工作流不直接拼装供应商 URL、header 或 payload；任何 Provider 都必须返回同一 `analysis.evidence/conflicts/gaps + decision` 合同，并通过本机 schema 和业务范围校验。
- 启用任一 Provider 后可以发送项目描述、业务板块、项目/待办元数据、相对文件名和修改时间、Git 提交元数据及早晨对话上下文。
- `PROJECT.md` 与可读文件正文默认只在本机分析；只有用户显式设置供应商无关的 `AI_SEND_FILE_CONTENT=1` 才允许出站。旧 `OPENAI_SEND_FILE_CONTENT=1` 仅在默认 `openai_luna` Profile 下作为兼容别名。
- 普通用户不能配置任意 endpoint、请求模板、header 或环境变量名。第三方 endpoint 必须命中部署 allowlist；公网只允许 HTTPS，本机匿名服务只允许显式 loopback。
- reasoning、strict schema 或 no-store 能力不足时默认拒绝调用；任何批准降级必须在运行状态中显示为 `degraded`。
- 配置凭证、doctor 通过或设置页显示“已配置”，都不等于模型已经联网调用成功或第三方 API 已通过真实验收。
- 本地文件夹仍是项目工作产物真源；飞书项目文档是项目叙事记忆真源；AI 输出本身不成为第三套资料真源。
