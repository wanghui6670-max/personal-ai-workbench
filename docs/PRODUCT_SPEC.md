# 产品规则（v1.2.0）

> 收件箱可绑定飞书每日工作日记。飞书文档中的一级“收件箱”章节是外部来源；只有 `[INBOX]` 前缀条目才进入工作台，其他日记正文不自动转任务。

## 产品定位

这是一个以业务板块和项目为上下文边界的个人 AI 项目管理工作台。目标不是增加任务管理动作，而是让用户在频繁被打断后快速恢复工作现场。

## 最高数据规则

**本地文件夹是真实工作产物源；Git 是版本证据源；飞书项目云文档是项目分析、阶段总结、复盘与长期叙事记忆的唯一真源；Workbench 只保存运行所需的最小结构化状态、引用、同步游标、幂等收据和恢复凭据。**

这意味着：

- 项目分析正文、卡点说明、恢复摘要、阶段总结和复盘正文不得复制进 `state.json`、`PROJECT.md`、activity 日志或浏览器持久化存储。
- Workbench 可以保存机器需要的 `percent / status / hasBlocker / lastActivity / syncedAt / confidence` 以及飞书 revision/block/operation 指针。
- `PROJECT.md` 只是项目身份证和入口索引，不是项目分析报告。
- 工作日志是机器审计日志，不等同于人的项目总结或项目记忆。
- 如果项目没有绑定飞书项目文档，系统仍可计算机器进度，但分析正文不持久化，并进入待确认。
- Capture 幂等收据只保存正文 SHA-256 和标识符，不保存采集正文。
- 项目记录恢复凭据只保存机器进度、operationId 和飞书指针，不保存分析或总结正文。
- 普通项目备忘仍可作为轻量本地记录；本规则专门约束项目分析、阶段总结、复盘和上下文恢复叙事。普通项目备忘是否迁移到飞书属于另一项产品决策。

## AI-native 双面板

- 左侧固定为人的工作面板，右侧固定为 AI 控制平面。
- 右侧 AI 通过 `ai_console` 提出白名单 MCP 工具调用或澄清问题；模型不能直接执行、访问任意 URL、shell、文件路径或凭证。
- MCP 注册表负责 schema 校验、确认门、领域规则和执行后状态读回。
- 模型未配置、不可达、输出不合约或参数不合法时，显式显示本地安全回退。
- 写入动作必须展示工具名、参数和影响范围并由用户确认。
- `panel_navigate` 只操作左侧导航，不改变业务状态。
- `project_records_read` 只从绑定飞书文档读取项目叙事。
- `project_summary_append` 只向绑定文档追加用户确认的阶段总结。

## 最高规则

**AI 可以分析、提醒、解释和执行明确指令，但不能替用户安排。**

以下动作必须由用户明确触发：

- 把任务加入今日工作台；
- 改变待办截止日期；
- 改变项目计划结束日期；
- 把独立待办升级成项目；
- 将收件箱内容移动到任何项目或待办；
- 把待归类项目归入业务板块；
- 向飞书项目文档追加人工阶段总结；
- 执行旧项目叙事迁移。

## 信息结构

1. 收件箱：所有新增事项第一站。
2. 今日工作台：用户当天明确决定要做的待办。
3. 业务板块：一级导航和一级本地文件目录。
4. 项目：独立上下文容器。
5. 待确认：AI 无法可靠判断或跨资源事务需要人工对账的事项。
6. 待归类：业务归属不明确的项目。
7. 逾期：只放超过计划结束时间、尚未结束的项目。
8. 工作日志：机器审计日志，不保存项目分析正文。
9. 飞书项目文档：项目分析、阶段总结、复盘和长期叙事记忆的唯一真源。

## 项目规则

- 创建输入：自然语言项目描述 + 计划结束日期。
- 开始日期：默认创建当天。
- 计划结束日期：必须由用户明确，AI 不猜。
- 名称和介绍：AI 自动生成；无 AI 时本地规则生成。
- 业务归属：AI 置信度足够时可创建到对应板块；不确定则待归类。
- 中间里程碑：不要求用户维护，由 AI 从项目内容识别。
- 不存在“暂停状态”。
- 第一次真实文件创建、修改、保存或 Git 提交，在下一次主动同步时被识别为进行中。
- 项目首页固定关注：介绍、机器进度、计划结束时间、是否存在卡点、资料路径和飞书项目文档入口。
- 项目首页提供“飞书项目记忆”面板，按需临时读取最近分析和总结。
- 不在项目首页自动生成下一步动作。

## 项目资料与记录边界

### 本地项目文件夹

默认目录：

```text
业务板块/
└── 项目/
    ├── PROJECT.md
    ├── 01_原始资料/
    ├── 02_工作过程/
    ├── 03_最终交付/
    └── 99_归档/
```

`PROJECT.md` 只保留：

- Project ID；
- 项目名称和介绍；
- 所属业务；
- 开始日期和计划结束日期；
- Git 仓库；
- 飞书项目文档 URL；
- “分析与总结真源：飞书云文档”声明。

新建和归类项目从第一次落盘起就写 identity-only `PROJECT.md`，不得先写旧叙事格式再补救覆盖。

`PROJECT.md` 不保存进度说明、卡点、恢复摘要、阶段总结或复盘正文。

### Workbench 本地状态

允许的项目机器进度字段：

```text
percent
status
hasBlocker
lastActivity
syncedAt
confidence
feishuRevisionId
feishuRecordBlockId
feishuRecordedAt
feishuOperationId
```

持久化校验器必须拒绝 `summary / resume / blocker` 等项目叙事字段。

### 飞书项目文档

每个项目最多绑定一个 `project.feishu`。项目文档必须是官方飞书/Lark HTTPS 云文档：

- host：`*.feishu.cn`、`*.larksuite.com`、`*.larkoffice.com`；
- path：`/wiki/<token>`、`/docx/<token>`、`/docs/<token>`；
- 不允许账号密码、查询参数、URL 片段或 HTTP。

工作台只操作固定一级章节：

```text
# 项目分析与总结
```

工作台记录格式：

```text
[WORKBENCH_ANALYSIS] [WORKBENCH_OP:<operationId>] ...
[WORKBENCH_SUMMARY] [WORKBENCH_OP:<operationId>] ...
```

- `WORKBENCH_ANALYSIS`：主动项目同步生成的分析报告。
- `WORKBENCH_SUMMARY`：用户确认后追加的阶段总结或复盘。
- 其他飞书正文不会被当作机器状态。
- 读取项目记录时直接读取飞书，不把正文缓存到本地状态。
- 项目页正文只保存在当前页面内存，不使用 `localStorage`、`sessionStorage` 或 IndexedDB。
- 读取最新记录优先，默认 20 条，硬上限 100，支持 cursor 分页。
- 单条阶段总结最大 6000 字符。
- 换绑或解绑文档时，旧 revision/block/operation 指针原子清除。

## 项目进度同步

- 不持续后台监控。
- 用户点击全部同步或单项目同步后才分析。
- 分析证据：目录文件、修改时间、文本片段、Git commit、Git remote。
- 默认 AI Provider Profile：`openai_luna`，模型 `gpt-5.6-luna`，推理档位 `xhigh`。
- 分析顺序：核对证据 → 标注冲突与信息缺口 → 结构化结论。
- 模型分析信封仅用于本次校验，不保存依据草稿或隐藏思维。
- 临时分析可以包含状态说明、百分比、卡点和恢复摘要；人类可读叙事只写飞书。
- 没有绑定飞书项目文档时，允许更新机器进度，但分析正文不落地，并新增待确认。
- 信息不足时进入待确认，不反复弹窗。
- 项目目录不存在或不可访问时，保留最后机器进度、降低置信度、不重建目录并进入待确认。
- Provider 失败时回退本地规则；不能因此改变收件箱、截止日期或今日任务，也不能自动转发到另一家云 Provider。

## 跨资源事务与幂等

项目分析和阶段总结写入采用：

```text
本地证据
→ 稳定 operationId
→ 本地恢复凭据
→ 飞书按 operationId 查重/写入
→ 飞书读回唯一 block
→ 本地提交机器状态和指针
→ 删除恢复凭据
```

- 同一 operationId 已存在时返回原 block，不重复追加。
- 同一 operationId 出现多个远端记录时停止并要求人工核对。
- `remote_pending`：远端调用尚未获得可确认结果。
- `remote_outcome_unknown`：请求失败，无法确定远端是否写入；重新同步先查重。
- `remote_saved_local_pending`：远端已读回，但本地状态未提交。
- 未解决的恢复凭据持续出现在待确认，不能被普通“清除待确认”永久隐藏。
- 恢复凭据不得包含项目分析或总结正文。

## 同步互斥

REST、右侧 AI 和 MCP 共用领域层同步协调器：

- 同一项目同时只能有一个同步；
- 全项目同步与任何单项目同步互斥；
- 冲突返回 `PROJECT_SYNC_BUSY`；
- 调用方不得并发自动重试。

## 旧版本迁移

- 首次启动检测到旧 `progress.summary/resume/blocker` 或旧同步日志时，必须先创建不可覆盖的原始快照。
- 快照固定入口：`data/migrations/pre-narrative-v1-startup.json`。
- 本地状态归一化后，项目进入 `legacy_project_narrative_pending` 待确认。
- 未绑定飞书的项目不能被标记为迁移完成。
- 迁移命令默认 dry-run；`--apply` 必须由用户明确执行。
- 旧 `PROJECT.md` 迁移前保存 `PROJECT.md.pre-feishu-v1.bak`，只替换工作台受管区块，保留用户正文。
- 损坏区块、错误 Project ID、symlink 或 hardlink 必须 fail closed。
- 迁移使用稳定 operationId，可重入且不重复写飞书。

完整操作说明见 `docs/PROJECT_RECORDS.md`。

## iPhone 与外部 Capture

- `/api/capture` 只接受有效登录会话或专用 Bearer `CAPTURE_TOKEN`。
- 每条新采集应由客户端生成唯一 `captureId`；同一条采集的所有不确定重试必须复用该 ID。
- 同 ID + 同正文返回第一次结果，不重复写飞书或本地收件箱。
- 同 ID + 不同正文返回 `CAPTURE_ID_CONFLICT`，不得覆盖。
- 原事项已经处理后再重试，不得把事项重新放回收件箱。
- `source` 是不可信兼容标签；持久化来源由服务端决定。
- Capture 绑定飞书数据源时采用“写飞书 → marker/block-ID 读回 → 本地收件箱提交 → 哈希收据”的顺序。
- 收据只保存正文 SHA-256、Capture ID、Inbox ID、飞书 block ID 和时间。
- 飞书凭证不得下发到 iPhone；iPhone 只持有独立 Capture token。

## 备份与恢复

- 自动每日快照和手工备份使用 backup v2。
- backup v2 必须包含精确字段 `state`、`config`、`captureReceipts` 和 `projectRecordReceipts`。
- 备份不得包含运行时派生的临时确认、Capture 正文、项目分析正文、`.env`、Provider/飞书凭证或真实项目工作区。
- 完整恢复必须在工作台停止写入时执行，并成组替换 state/config/两类凭据。
- `projectRecordReceipts[*].projectId` 必须引用恢复状态中真实存在的项目；悬空引用必须在创建数据目录或执行任何写入前拒绝。
- 任一恢复阶段失败时，必须尝试把所有已修改部分回滚到恢复前安全备份。
- 旧备份没有凭据字段时，保留当前凭据目录，不得静默清空；同时明确旧备份不是这些凭据的历史快照。
- `GET /api/export` 只用于导出 state/config，不等同于完整恢复包。

## 待办

- 项目待办和独立待办都允许。
- 新待办必须从收件箱经过用户指令产生。
- 必须有截止日期，只精确到日期。
- 用户没说截止日期时必须追问。
- 截止日期到了也不会自动进入今日工作台。
- 项目名匹配不唯一时，收件箱保持原状，由用户选择目标项目。

## 今日工作台与早晨对焦

AI 默认分析：

- 最近 3 天真实工作；
- 最近 3 天新待办；
- 临近截止的项目和待办。

逾期项目只进入逾期目录。AI 提出值得讨论的事项，用户最终决定哪些待办加入今日。无论 AI 成功还是本地回退，都不能直接写入今日计划。

今日选择按服务机器自然日记录；昨日选择不会自动沿用。

## AI Provider 与数据边界

- 默认 `openai_luna` 保持 OpenAI Responses API 行为；第三方兼容 Profile 默认关闭。
- Provider 必须返回统一 `analysis.evidence/conflicts/gaps + decision` 合同并通过本机校验。
- 可发送项目描述、业务板块、项目/待办元数据、相对文件名和修改时间、Git 提交元数据及对话上下文。
- 文件正文默认只在本机分析；只有显式设置 `AI_SEND_FILE_CONTENT=1` 才允许出站。
- 普通用户不能配置任意 endpoint、header 或环境变量名。
- reasoning、strict schema 或 no-store 能力不足时默认拒绝；批准降级必须显示为 `degraded`。
- 配置凭证或 doctor 通过不等于真实联网验收。
- AI 输出本身不成为第三套资料真源。
