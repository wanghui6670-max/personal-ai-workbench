# Personal AI Workbench v3 — 信息来源与 AI 处理合同

> 状态：**Normative / 当前有效**  
> 生效日期：2026-08-16  
> 本文档是 Personal AI Workbench v3 的个人待办来源、飞书同步、AI 权限与 Today 所有权的最高优先级产品合同。与本文冲突的旧 GetNote Task Sync、旧“整篇飞书日记同步”或旧“从日记提取待办”描述均只视为历史兼容说明。

## 1. 一句话合同

```text
待办来源：飞书云文档中的明确待办
→ 用户主动点击同步
→ 只读取显式待办 block
→ 精确去重
→ Workbench 待处理
→ AI 可围绕这条待办给建议
→ 用户确认
→ Workbench Todo
→ 是否加入 Today 再由用户决定

普通日记 / 复盘 / 分析 / 项目进展：留在飞书，不进入待办同步
内容素材：得到大脑 GetNote → 用户确认同步 → 自媒体内容库
状态真相：Workbench state
```

Workbench 本地 `state.json` 继续是任务状态、用户决定、Today 选择、项目归属等个人状态的真相源。

**待办同步不得读取整篇飞书日记再让 AI 猜哪些内容是任务。**

## 2. 什么算“飞书云文档中的待办”

待办同步只接受明确的待办结构，不做语义猜测。

当前允许进入待办同步的来源只有：

1. **飞书原生未完成待办 / 复选框类 block**：当前解析兼容 `checkbox / task / todo` 形式；已标记 `checked / done / completed` 的 block 不作为新待办导入。
2. **明确收件箱中的 `[INBOX]` 条目**：仅兼容配置的 `收件箱` 一级章节，或 Workbench 自己创建的 `Workbench 收件箱` 一级章节中的 `[INBOX]` 条目。

以下内容即使看起来“像任务”，也**不得**进入待办同步：

- 普通 `p` 段落；
- 普通列表项；
- 工作日记；
- 复盘；
- 分析、观点、结论、策略；
- 项目进展；
- 日常流水；
- “以后注意”“要重视”“记住”之类没有显式待办结构的文字；
- AI 从上述文字中推测出的动作。

因此，**飞书原文可以继续自由记录，用户不需要为了 Workbench 改写日记格式。待办同步只读取其中本来就是待办的部分。**

## 3. 同步必须由用户主动触发

同步接口仍为 `/api/inbox/sync`；兼容 MCP 工具名继续使用 `feishu_inbox_sync`。

硬规则：

- 打开或刷新 Workbench 不自动拉取飞书；
- 只有用户点击 **“同步飞书待办”** 才允许读取飞书来源；
- “初始化待办同步 / 重新初始化待办”同样必须由用户显式确认；
- AI 分析不能反向触发飞书同步；
- 右侧助手不能绕过同步门读取普通飞书日记。

## 4. Todo-only 解析合同

飞书客户端读取文档后执行 `todo_only` 解析：

```text
飞书云文档
→ 找原生未完成待办 / 复选框
→ 找明确收件箱里的 [INBOX]
→ 忽略其他所有正文
→ 返回 mode = todo_only
```

`mixed_diary` 解析器可以暂时留在代码库作为历史兼容/回归材料，但**不得再作为当前待办同步入口的运行路径**。

`diary_extract_todos` 旧工具可以暂时保留源码用于历史回归，但**不得注册到当前交互式 MCP / AI 工具面**。

## 5. 去重与来源身份

待办来源继续采用保守规则：

- `blockId` 是飞书来源身份；
- 已见过的明确待办 block 会保留在 `inboxAcks`；
- 普通同步不会因为同一个 block 后续编辑而再次创建一条新待办；
- 同一批明确待办先按规范化正文做精确去重；
- 同时检查当前 Inbox、已建立 Todo 与兼容 Notes，避免完全相同的待办重复进入；
- 规范化可以使用 Unicode NFKC、空白折叠与 trim；
- **不得用模糊语义相似度自动删除两个不同待办。**

Workbench 本地删除一条已同步待办，不删除飞书原文。

## 6. 从旧“整篇日记解析”迁移

历史版本曾把飞书 `mixed_diary` 普通段落导入 Workbench，并生成 `feishu_todo_candidate`。

从本合同生效起，这些都不是当前待办来源。

用户第一次执行“同步飞书待办”或“初始化待办同步”时：

- 自动撤下本地 `feishu_todo_candidate`；
- 自动撤下 `source=feishu_doc + feishuMode=mixed_diary` 的旧原始日记项；
- 删除这些旧项对应的本地待确认记录；
- **不删除、不修改飞书原文**；
- 如果某个旧来源 block 在当前飞书文档中本身就是明确待办，则释放该来源旧 ACK，并按 `todo_only` 新规则重新导入；
- 普通日记 block 的 ACK 可以继续保留，避免历史日记再次进入旧链路。

这意味着历史上一次性出现的几百条日记内容，不需要用户逐条手工删除。

## 7. AI 的职责

AI 不负责“从日记找任务”。

AI 只可以对**已经由飞书结构明确证明是待办**的单条内容做处理建议。

单条待办 AI 上下文最多包含：

- 当前目标待办正文；
- 当前待办的标题路径 / 类型；
- 最多 30 个未归档项目的目录级摘要。

不得发送：

- 其他飞书日记正文；
- 其他 Inbox 原文；
- Todo 列表正文；
- Today；
- confirmations；
- 项目长介绍或项目文档正文；
- 其他无关私人记录。

单条审阅只允许：

- `inbox_process`：针对当前明确待办生成处理预览。

以下能力在飞书待办审阅中禁止：

- `diary_extract_todos`；
- 跨 item 操作；
- 自动新建项目；
- 自动加入 Today；
- 自动删除飞书原文；
- 猜截止日期；
- 猜项目归属。

缺截止日期、项目不唯一、需要新建项目或信息不足时必须 clarification。

## 8. Workbench 待处理与 Today

飞书同步进入 Workbench 后，内容仍然只是“待处理的明确待办”，不等于自动加入 Today。

默认工作面展示：

- 今天已经由用户明确确认的 Todo；
- 从飞书云文档同步来的明确待办；
- AI 针对这些待办的处理建议；
- 少量需要用户补日期 / 项目 / 决策的事项。

`todayPlan` 与 Todo 是不同领域对象：

- AI 可以建议；
- 创建 Todo 需要遵守现有领域校验；
- **是否加入 Today 始终由用户决定。**

## 9. 初始化 / 重新初始化待办

“初始化待办同步”只建立明确待办的来源基线，不再把整篇日记灌入 Workbench。

“重新初始化待办”可以：

- 清空当前待办来源 ACK 基线；
- 重新扫描当前飞书云文档；
- 只识别明确待办；
- 重建待办来源状态。

它不得：

- 把普通日记送 AI 做待办提取；
- 删除飞书原文；
- 移动飞书段落；
- 自动创建 Today；
- 自动创建项目。

## 10. Workbench 向飞书写入

Workbench / iPhone Capture 产生的新事项如果需要写入已绑定飞书文档：

- 优先写入配置的 `收件箱`；
- 如果不存在，则使用/创建 `Workbench 收件箱`；
- Workbench 自己写入的明确事项使用 `[INBOX]` 前缀；
- 不插入、不重排、不改写用户普通日记正文。

这些 `[INBOX]` 条目属于显式待办兼容来源，因此可进入 todo-only 同步合同。

## 11. 得到大脑与项目记录边界

### 11.1 GetNote

得到大脑不进入个人待办主链路，只保留自媒体内容来源：

- `getnote_content_status`：只读；
- `getnote_content_sync`：用户确认后同步可验证真实原文到本地内容库。

旧 `external_tasks_sync` / `external_task_integration_update` 不得重新注册为个人待办主来源。

### 11.2 项目记录

个人飞书云文档里的普通项目进展不通过待办同步进入 Workbench。

项目分析正文和总结继续只通过明确的项目记录链写入绑定的飞书项目文档；机器状态仍由 Workbench state 管理。

## 12. 不可回退的硬约束

1. **待办同步只同步飞书云文档中的明确待办。**
2. 普通日记正文不进入待办同步。
3. 不从普通日记调用 AI 提取待办。
4. 原生已完成待办不作为新的待办候选导入。
5. `[INBOX]` 只在明确收件箱章节内视为待办兼容标记。
6. 不猜截止日期。
7. 不猜项目。
8. 不自动新建项目。
9. 不自动加入 Today。
10. 不删除或改写飞书原文。
11. Provider 只接收当前明确待办 + 有界项目目录摘要。
12. 旧日记解析项迁移由系统自动清理，不要求用户逐条删除。
13. `diary_extract_todos` 不得出现在当前交互式工具注册面。

## 13. 当前推荐链路

```text
用户打开 Workbench
→ 只读本地状态

用户点击“同步飞书待办”
→ 读取飞书云文档
→ 只筛显式未完成待办 / 明确收件箱 [INBOX]
→ 普通日记直接忽略
→ 精确去重
→ 明确待办进入 Workbench 待处理
→ AI 只围绕这条待办给建议
→ 用户补齐日期 / 项目（如需要）
→ 用户确认创建/处理 Todo
→ 是否加入 Today 再由用户决定
```

这条链路是当前 v3 的规范性个人待办主链。
